# M1: Supabase schema, RLS and auth Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The linked Supabase project has every table from PRD section 5, plus form limits, with RLS on every table and explicit GRANTs, built only from migration files.

**Architecture:** Five migration files under `supabase/migrations/`, applied with `supabase db push`. Form limits are generated from `js/config.js` by a small Node script, so the limit check in the browser and the `v_near_limit` view use the same numbers; a second script compares the live database with the config. Views run with `security_invoker` so RLS still applies through them.

**Tech Stack:** Postgres 17 on Supabase, Supabase CLI 2.122, Node 22 (`node --test`, no dependencies).

**Who does what:** Claude drafts every file. The user reads each migration, writes the `flights` read policy (Task 4), runs `supabase db push` (Task 7) and tests RLS in the SQL Editor (Task 8). Nothing is committed until the user says so.

**Constraints:**
- No Docker on this machine, so there is no local database. SQL is checked on the linked project after the push. Read-only checks run with `supabase db query --linked`, which uses the saved login token and never needs the database password.
- The CLI crashes on interactive prompts in the user's terminal. Before `db push`, set the password without a prompt: `read -s "SUPABASE_DB_PASSWORD?DB password: " && export SUPABASE_DB_PASSWORD`.
- "Automatically expose new tables" is off, so every table and view needs a GRANT or the app can't see it.
- Auth is already set up in the dashboard: public sign-ups are off and the demo user exists (auto-confirmed). Its credentials live in the user's password manager, never in the repo.
- `created_by` defaults to `auth.uid()`, which is null for `service_role`. The M3 seed must set `created_by` to the demo user's id explicitly.
- `anon` (not logged in) gets no grants at all. `service_role` (used later by the edge function) gets full access and bypasses RLS.

## Design decisions

- **IDs are `uuid`** (`gen_random_uuid()`). In M2 the browser can create them with `crypto.randomUUID()` before saving, which keeps the current `alloc[rowId]` mapping intact.
- **`dest` has no foreign key to an airport list.** The M3 seed plants a bad destination on purpose (PRD pattern 6), and the app already warns on unknown codes.
- **Weights are `numeric(8,1)` with `check (>= 0)`.** The typed text, including expressions like `100+45`, is kept in `flight_stops.raw_entry`.
- **Closed flights are read-only.** Updates and deletes on `flights`, and all writes to stops and allocations, require the parent flight to be `draft`. The update policy's `using` checks the row before the change (must be draft) and its `with check` checks it after (draft or closed), so closing works and reopening doesn't.
- **`created_by` can't be changed.** `flights` grants UPDATE column by column and leaves out `id`, `created_by` and `created_at`.
- **An allocation's stop must be on the same flight**, enforced by a two-column foreign key.
- **Shared ops data.** Any logged-in user can read and edit draft flights, like a shared ops board. `created_by` records who made each flight.
- **Near-limit threshold is 95% of max**, matching PRD pattern 2 ("within 5%").
- **`forms.capacity_lb`** is the most a form can carry: each zone's max, except zones covered by a combined-zone group count the group max once. It is the denominator for the load-factor proxy in `v_route_week`.
- **Route** in `v_route_week` is the flight's stops in order, joined with `-` (for example `YSB-YTS`).

- [ ] **Step 4: Write `scripts/forms-sql.mjs`**

```js
#!/usr/bin/env node
/* Turns FORMS in js/config.js into SQL that upserts forms, form_zones and form_groups.
   Usage: node scripts/forms-sql.mjs > supabase/migrations/<timestamp>_forms_data.sql
   The browser's limit check and the database read the same numbers this way. */
import { pathToFileURL } from 'node:url';
import { FORMS } from '../js/config.js';

const holdsFreight = z => !z.na && !z.unavailable;
const q = s => `'${String(s).replace(/'/g, "''")}'`;

// Widest groups first; a group inside one already counted adds nothing.
export function capacityOf(form) {
  const counted = [];
  [...form.groups].sort((a, b) => b.zones.length - a.zones.length).forEach(g => {
    if (!counted.some(c => g.zones.every(id => c.zones.includes(id)))) counted.push(g);
  });
  const inGroup = new Set(counted.flatMap(g => g.zones));
  const loose = form.zones.filter(z => holdsFreight(z) && z.max && !inGroup.has(z.id));
  return counted.reduce((s, g) => s + g.max, 0) + loose.reduce((s, z) => s + z.max, 0);
}

export function formRows(forms) {
  const entries = Object.entries(forms);
  return {
    forms: entries.map(([id, f]) => ({ form_id: id, aircraft_type: f.type, name: f.name, is_split: !!f.split, capacity_lb: capacityOf(f) })),
    zones: entries.flatMap(([id, f]) => f.zones.filter(holdsFreight)
      .map((z, i) => ({ form_id: id, zone_id: z.id, label: z.label, max_lb: z.max ?? null, seq: i }))),
    groups: entries.flatMap(([id, f]) => f.groups
      .map(g => ({ form_id: id, group_id: g.id, label: g.short || g.label, zone_ids: g.zones, max_lb: g.max }))),
  };
}

export function formsSql(forms) {
  const { forms: fs, zones, groups } = formRows(forms);
  const v = x => x === null ? 'null' : typeof x === 'string' ? q(x) : Array.isArray(x) ? `array[${x.map(q).join(',')}]` : String(x);
  const values = rows => rows.map(r => `  (${Object.values(r).map(v).join(', ')})`).join(',\n');
  return `-- Generated by scripts/forms-sql.mjs from js/config.js. Do not edit by hand.
-- Illustrative limits, not from any real aircraft.

insert into public.forms (form_id, aircraft_type, name, is_split, capacity_lb) values
${values(fs)}
on conflict (form_id) do update set aircraft_type = excluded.aircraft_type, name = excluded.name,
  is_split = excluded.is_split, capacity_lb = excluded.capacity_lb;

insert into public.form_zones (form_id, zone_id, label, max_lb, seq) values
${values(zones)}
on conflict (form_id, zone_id) do update set label = excluded.label, max_lb = excluded.max_lb, seq = excluded.seq;
${groups.length ? `
insert into public.form_groups (form_id, group_id, label, zone_ids, max_lb) values
${values(groups)}
on conflict (form_id, group_id) do update set label = excluded.label, zone_ids = excluded.zone_ids, max_lb = excluded.max_lb;
` : ''}`;
}

if (import.meta.url === pathToFileURL(process.argv[1]).href) process.stdout.write(formsSql(FORMS));
```

```sql
-- Form definitions and their weight limits. The rows come from js/config.js
-- (see the next migration), so the database and the browser agree on every limit.

create table public.forms (
  form_id       text primary key,              -- matches the key in FORMS, e.g. 'DH8300'
  aircraft_type text not null,
  name          text not null,
  is_split      boolean not null default false, -- true: bags and cargo recorded separately per zone
  capacity_lb   numeric(8,1) not null check (capacity_lb > 0)
);

create table public.form_zones (
  form_id text not null references public.forms on delete cascade,
  zone_id text not null,
  label   text not null,
  max_lb  numeric(8,1) check (max_lb > 0),     -- null: no limit printed for this zone
  seq     int not null,                         -- left-to-right order on the form
  primary key (form_id, zone_id)
);

-- A combined-zone limit, e.g. "Zone 1A + 1B together max 1,700 lb".
create table public.form_groups (
  form_id  text not null references public.forms on delete cascade,
  group_id text not null,
  label    text not null,
  zone_ids text[] not null check (cardinality(zone_ids) > 1),
  max_lb   numeric(8,1) not null check (max_lb > 0),
  primary key (form_id, group_id)
);

-- RLS: logged-in users can read the limits. Nobody writes them from the app;
-- they change only through a migration.
alter table public.forms       enable row level security;
alter table public.form_zones  enable row level security;
alter table public.form_groups enable row level security;

create policy "logged-in users read forms"       on public.forms       for select to authenticated using (true);
create policy "logged-in users read form zones"  on public.form_zones  for select to authenticated using (true);
create policy "logged-in users read form groups" on public.form_groups for select to authenticated using (true);

-- GRANTs: "automatically expose new tables" is off, so nothing is reachable until granted.
-- anon (not logged in) gets nothing.
grant select on public.forms, public.form_zones, public.form_groups to authenticated;
grant all    on public.forms, public.form_zones, public.form_groups to service_role;
```

```sql
-- Flights and their manifest. Maps the app's flight object:
--   flight fields -> flights, rows -> flight_stops, alloc -> zone_allocations, pos -> flights.tag_positions

create table public.flights (
  id                uuid primary key default gen_random_uuid(),
  flight_date       date not null,
  flight_no         text not null default '',
  registration      text not null default '',
  form_id           text not null references public.forms,
  etd               time,
  actual_departure  time,
  delay_minutes     int check (delay_minutes >= 0),
  special_hr        boolean not null default false,
  special_aog       boolean not null default false,
  dg_note           text not null default '',
  loadmaster        text not null default '',
  notes             text not null default '',
  manual_alloc      boolean not null default false,  -- true once the user edits allocations by hand
  tag_positions     jsonb not null default '{}',     -- print layout only; the app's `pos`
  status            text not null default 'draft' check (status in ('draft', 'closed')),
  created_by        uuid not null default auth.uid() references auth.users,
  created_at        timestamptz not null default now(),
  updated_at        timestamptz not null default now()
);
create index flights_date_idx on public.flights (flight_date);

create table public.flight_stops (
  id        uuid primary key default gen_random_uuid(),
  flight_id uuid not null references public.flights on delete cascade,
  seq       int not null,                  -- manifest order, 0 first
  dest      text not null default '',      -- no airport foreign key: the seed plants a bad code on purpose
  cargo_lb  numeric(8,1) not null default 0 check (cargo_lb >= 0),
  post_lb   numeric(8,1) not null default 0 check (post_lb >= 0),
  fast_lb   numeric(8,1) not null default 0 check (fast_lb >= 0),
  bag_lb    numeric(8,1) not null default 0 check (bag_lb >= 0),
  raw_entry jsonb not null default '{}',   -- cells as typed, e.g. {"cargo": "100+45"}
  unique (flight_id, seq) deferrable initially deferred,  -- lets the app reorder stops in one transaction
  unique (id, flight_id)                   -- target for the allocation foreign key below
);

create table public.zone_allocations (
  id        uuid primary key default gen_random_uuid(),
  flight_id uuid not null references public.flights on delete cascade,
  stop_id   uuid not null,
  kind      text not null check (kind in ('bag', 'cargo', 'all')),
  zone_id   text not null,
  weight_lb numeric(8,1) not null check (weight_lb >= 0),
  unique (stop_id, kind, zone_id),
  -- the stop must belong to the same flight, so an allocation can't be filed
  -- under a draft flight while pointing at a closed flight's stop
  foreign key (stop_id, flight_id) references public.flight_stops (id, flight_id) on delete cascade
);
create index zone_allocations_flight_idx on public.zone_allocations (flight_id);
create index flight_stops_flight_idx on public.flight_stops (flight_id);

-- Keep updated_at current on every edit.
create function public.touch_updated_at() returns trigger
language plpgsql set search_path = '' as $$
begin
  new.updated_at := now();
  return new;
end $$;
create trigger flights_touch before update on public.flights
  for each row execute function public.touch_updated_at();

-- ---------- RLS ----------
alter table public.flights          enable row level security;
alter table public.flight_stops     enable row level security;
alter table public.zone_allocations enable row level security;

-- flights: read
-- YOUR POLICY HERE (Task 4, Step 2)

-- flights: any logged-in user can create a flight; created_by must be themselves.
create policy "logged-in users create flights" on public.flights
  for insert to authenticated
  with check (created_by = (select auth.uid()));

-- flights: edit while draft. `using` checks the row before the change (must be draft);
-- `with check` checks the row after it. Without `with check`, Postgres reuses `using`
-- for the new row too, and closing a flight (draft -> closed) would be rejected.
-- Closed flights can't be edited or reopened because they fail `using`.
create policy "logged-in users edit draft flights" on public.flights
  for update to authenticated
  using (status = 'draft')
  with check (status in ('draft', 'closed'));

create policy "logged-in users delete draft flights" on public.flights
  for delete to authenticated
  using (status = 'draft');

-- stops and allocations follow their flight: readable always, writable only while it's draft.
create policy "read stops" on public.flight_stops
  for select to authenticated using (true);
create policy "write stops of draft flights" on public.flight_stops
  for all to authenticated
  using      (exists (select 1 from public.flights f where f.id = flight_id and f.status = 'draft'))
  with check (exists (select 1 from public.flights f where f.id = flight_id and f.status = 'draft'));

create policy "read allocations" on public.zone_allocations
  for select to authenticated using (true);
create policy "write allocations of draft flights" on public.zone_allocations
  for all to authenticated
  using      (exists (select 1 from public.flights f where f.id = flight_id and f.status = 'draft'))
  with check (exists (select 1 from public.flights f where f.id = flight_id and f.status = 'draft'));

-- ---------- GRANTs ----------
-- flights: update is granted column by column, leaving out id, created_by and created_at,
-- so nobody can reassign who made a flight. (M2: save with update, not an upsert that
-- sends every column.)
grant select, insert, delete on public.flights to authenticated;
grant update (flight_date, flight_no, registration, form_id, etd, actual_departure, delay_minutes,
              special_hr, special_aog, dg_note, loadmaster, notes, manual_alloc, tag_positions,
              status, updated_at)
  on public.flights to authenticated;
grant select, insert, update, delete on public.flight_stops, public.zone_allocations to authenticated;
grant all on public.flights, public.flight_stops, public.zone_allocations to service_role;
```

### Task 6: Views migration

**Files:**
- Create: `supabase/migrations/20261027090400_views.sql`

- [ ] **Step 1: Write the migration**

```sql
-- Deterministic aggregates for the weekly report. security_invoker = true makes each
-- view run with the caller's permissions, so RLS on the tables underneath still applies.
-- Without it a view runs as its owner and would skip RLS.

-- Total placed weight per flight and zone (all stops and kinds), as in the app's compute():
-- only stops with a destination or a weight, and only zones on the flight's current form
-- (allocations left over from a form change don't count).
create view public.v_zone_loads with (security_invoker = true) as
select a.flight_id, a.zone_id, sum(a.weight_lb) as load_lb
from public.zone_allocations a
join public.flight_stops s on s.id = a.stop_id
join public.flights f on f.id = a.flight_id
join public.form_zones z on z.form_id = f.form_id and z.zone_id = a.zone_id
where s.dest <> '' or s.cargo_lb + s.post_lb + s.fast_lb + s.bag_lb > 0
group by a.flight_id, a.zone_id;

-- Flights at or above 95% of any zone or combined-zone limit.
create view public.v_near_limit with (security_invoker = true) as
with checks as (
  select f.id as flight_id, 'zone' as limit_kind, z.zone_id as limit_id, z.label,
         coalesce(l.load_lb, 0) as load_lb, z.max_lb
  from public.flights f
  join public.form_zones z on z.form_id = f.form_id and z.max_lb is not null
  left join public.v_zone_loads l on l.flight_id = f.id and l.zone_id = z.zone_id
  union all
  select f.id, 'group', g.group_id, g.label,
         coalesce((select sum(l.load_lb) from public.v_zone_loads l
                   where l.flight_id = f.id and l.zone_id = any (g.zone_ids)), 0),
         g.max_lb
  from public.flights f
  join public.form_groups g on g.form_id = f.form_id
)
select f.id as flight_id, f.flight_date, f.flight_no, f.registration, f.form_id,
       c.limit_kind, c.limit_id, c.label, c.load_lb, c.max_lb,
       round(c.load_lb / c.max_lb, 3) as pct_of_max,
       c.load_lb > c.max_lb as is_over
from checks c
join public.flights f on f.id = c.flight_id
where c.load_lb >= 0.95 * c.max_lb;

-- Freight per route per week. Route is the stops in order, e.g. 'YSB-YTS'.
-- load_factor_proxy: placed weight / form capacity, averaged over the week's flights.
create view public.v_route_week with (security_invoker = true) as
with per_flight as (
  select f.id, f.flight_date, f.form_id,
         string_agg(s.dest, '-' order by s.seq) as route,
         sum(s.cargo_lb) as cargo_lb, sum(s.post_lb) as post_lb,
         sum(s.fast_lb) as fast_lb, sum(s.bag_lb) as bag_lb
  from public.flights f
  join public.flight_stops s on s.flight_id = f.id
  where s.dest <> '' or s.cargo_lb + s.post_lb + s.fast_lb + s.bag_lb > 0
  group by f.id
)
select date_trunc('week', p.flight_date)::date as week_start, p.route, p.form_id,
       count(*) as flights,
       sum(p.cargo_lb) as cargo_lb, sum(p.post_lb) as post_lb,
       sum(p.fast_lb) as fast_lb, sum(p.bag_lb) as bag_lb,
       sum(p.cargo_lb + p.post_lb + p.fast_lb + p.bag_lb) as total_lb,
       round(avg(coalesce(l.placed_lb, 0) / fm.capacity_lb), 3) as load_factor_proxy
from per_flight p
join public.forms fm on fm.form_id = p.form_id
left join (select flight_id, sum(load_lb) as placed_lb from public.v_zone_loads group by flight_id) l
  on l.flight_id = p.id
group by 1, 2, 3;

-- Delays per day.
create view public.v_delays with (security_invoker = true) as
select f.flight_date,
       count(*) as flights,
       count(*) filter (where f.delay_minutes > 0) as delayed_flights,
       coalesce(sum(f.delay_minutes), 0) as total_delay_minutes,
       max(f.delay_minutes) as max_delay_minutes
from public.flights f
group by f.flight_date;

grant select on public.v_zone_loads, public.v_near_limit, public.v_route_week, public.v_delays
  to authenticated, service_role;
```

```sql
-- Run in the Supabase SQL Editor, one block at a time. Each block pretends to be a
-- different caller and rolls back, so nothing is saved.
-- Pass: "Success. No rows returned". Fail: an error whose message starts with FAIL.
-- Blocks 2 and 3 log in as the demo user automatically (the only user in auth.users).

-- 1. Not logged in: anon has no GRANT, so reading flights must be refused.
begin;
set local role anon;
do $$ begin
  perform count(*) from public.flights;
  raise exception 'FAIL: anon could read flights';
exception when insufficient_privilege then null;  -- refused, as expected
end $$;
rollback;

-- 2. Logged in: create a draft flight, read it, close it, then try to edit it.
begin;
select set_config('request.jwt.claims',
  json_build_object('sub', (select id from auth.users order by created_at limit 1), 'role', 'authenticated')::text, true);
set local role authenticated;
do $$
declare n int;
begin
  insert into public.flights (flight_date, flight_no, form_id) values (current_date, 'RLS1', 'PC12');
  select count(*) into n from public.flights where flight_no = 'RLS1';
  assert n = 1, 'FAIL: logged-in user could not read the flight they created';

  update public.flights set status = 'closed' where flight_no = 'RLS1';
  get diagnostics n = row_count;
  assert n = 1, 'FAIL: could not close a draft flight';

  update public.flights set notes = 'edited' where flight_no = 'RLS1';
  get diagnostics n = row_count;
  assert n = 0, 'FAIL: a closed flight was edited';

  begin
    update public.flights set created_by = gen_random_uuid() where flight_no = 'RLS1';
    raise exception 'FAIL: created_by could be changed';
  exception when insufficient_privilege then null;
  end;
end $$;
rollback;

begin;
select set_config('request.jwt.claims',
```

```js
#!/usr/bin/env node
/* Fails if the form limits in the linked database differ from js/config.js.
   Uses the saved CLI login; never needs the database password. */
import { execFileSync } from 'node:child_process';
import { FORMS } from '../js/config.js';
import { formRows } from './forms-sql.mjs';

const query = sql => {
  const out = execFileSync('supabase', ['db', 'query', '--linked', '--output-format', 'json', sql], { encoding: 'utf8' });
  const parsed = JSON.parse(out);
  return parsed.rows ?? parsed;
};
const key = r => JSON.stringify(Object.keys(r).sort().map(k => [k, Array.isArray(r[k]) ? r[k] : r[k] === null ? null : String(Number(r[k]) || r[k])]));
const same = (a, b) => JSON.stringify(a.map(key).sort()) === JSON.stringify(b.map(key).sort());

const want = formRows(FORMS);
const got = {
  forms: query('select form_id, aircraft_type, name, is_split, capacity_lb from public.forms'),
  zones: query('select form_id, zone_id, label, max_lb, seq from public.form_zones'),
  groups: query('select form_id, group_id, label, zone_ids, max_lb from public.form_groups'),
};
const bad = Object.keys(want).filter(t => !same(want[t], got[t]));
if (bad.length) {
  console.error(`Out of sync with js/config.js: ${bad.join(', ')}. Generate a new migration with scripts/forms-sql.mjs.`);
  process.exit(1);
}
console.log('Form limits in the database match js/config.js.');
```
